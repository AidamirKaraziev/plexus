# Закрыть — одна дверь из работы

Корень Плексуса — `${CLAUDE_PLUGIN_ROOT}`; в Codex эта строка не раскрывается — бери путь из строки контекста «корень Плексуса: …», а если её нет — папку на два уровня выше этого SKILL.md.

Speak Russian to the user throughout. Скрипты — в `${CLAUDE_PLUGIN_ROOT}/lib/`.

Хвост сессии — привычный пайплайн человека: проверить, записать знания,
забрать работу, закоммитить, отметить план, убрать. **Очевидные шаги не
спрашивать — делать.** Вопрос только там, где настоящий выбор: `проверка:
человек`, конфликт при переносе, удаление устаревших заметок, несколько
своих замков.

## 0. Какой круг

Свой замок: `.claude/locks/<круг>.json`, где `кто` = `git config user.name`.
Замков-своих нет или несколько → AskUserQuestion, какой закрывать.

Открытого круга нет → одна строка «нечего закрывать»; незакоммиченное
этой сессии — закоммитить по §8 (п. 3–4), чужое — назвать строкой.

## 1. Чек-лист

`python3 lib/экран_выхода.py --чеклист <круг>` — два уровня: круг (задачи
✓/○) и эпик (этапы ✓/○, `← этот круг`). Показать как есть. Последняя
строка вывода — `продолжить: /plexus:start <id>` или `круг закрыт`.

## 2. Проверить, а не поверить

Для каждой задачи круга выполнить её `проверка:` — ту самую команду, не
похожую. `проверка: человек` — показать критерий и спросить одной строкой.

Упала → задача с ✗ и строкой «почему». Чинить здесь нельзя. Не сошлось
много — сказать прямо, что круг не закрыт.

## 3. Итог в файл круга

Экран — как в §7 `/plexus:task`: задача · время · токены · окно ·
проверка, успешная одной строкой, разворачиваются только ✗ и ⚠. Цифры
берёт `lib/spend.py`, не человек и не работник. Тот же текст — в раздел
«Итог» файла круга.

## 4. Знания

Решения, баги, тупики, паттерны из круга записать сразу, без списка на
утверждение; не заметка — то, что уже лежит заметкой с этого круга,
значение по умолчанию, косметика. По каждому:

```
python3 lib/заметка.py --новая <решение|баг|тупик|паттерн> --имя "<утверждение>" --эпик <E..> --круг "<имя>"
```

Печатает путь заготовки — заполнить разделы, затем `заметка.py --проверить
<файл>` (нужен код 0). Код 2 на имени — Windows его не примет: переименовать,
не обходить.

Устаревшее: `заметка.py --устаревшие <файл>` даёт кандидатов; отсечь лишние,
показать человеку списком; удалить только после «да» — это единственный
вопрос раздела, и он не держит остальной хвост.

Ничего заметного нет — раздел молча пропустить.

## 5. Передача или закрытие

Круг не закрыт: черновик передачи записать во временный файл, затем
`python3 lib/экран_выхода.py --передача <круг> --из <черновик.md>`. Разделы
строго в порядке: Сделано, Остановились на, Ждёт тебя, Читать только
(файлы со строками), Проверка (команда и последний результат), Рабочая
копия, Не повторять (с причиной), Первый шаг, Продолжить
(`/plexus:start <id>`). Не больше 5 строк в разделе, пустые не писать.
Код 2 → сократить по причине и повторить.

Все задачи ✓: `экран_выхода.py --закрыть <круг>` — удаляет передачу,
круг уходит в `vault/круги/архив/`. Код 2 → круг не закрыт, вернуться к
передаче.

## 6. Журнал

`python3 lib/экран_выхода.py --журнал <круг> --статус закрыт|пауза`.

## 7. Анализатор

Перед коммитом: `cd "${CLAUDE_PLUGIN_ROOT}/lib" && python3 аналитика.py --порог`.
«звать: нет» → не показывать. «звать: да» → спросить одной строкой с числом
сигналов, звать ли `/plexus:analyst`; «нет» ничего не ломает.

## 8. Хвост без вопросов

Строго по порядку, ничего не спрашивая:

1. `python3 lib/уборка.py --забрать` — коммиты принятых задач в ветку
   человека. Конфликт → остановиться, показать файлы; это вопрос.
2. `python3 lib/youtrack.py` — до `git add`, чтобы ключ `youtrack:` попал
   в коммит. «Не настроен» не выводить; код 3 — строка на экран, хвост
   продолжается.
3. `git add` — только файлы этого круга и сессии: vault, отчёты круга,
   журнал, план. Чужое незакоммиченное не добавлять, назвать строкой.
4. `git commit` — текст в стиле репозитория, например
   `docs(круг): <имя> — круг закрыт, решения и отчёты`.
5. Круг закрыт (все ✓) → этап из `этап:` файла круга отметить в подплане:
   `- [ ] SNN …` → `- [x] SNN … · <SHA коммита из п. 4>`; затем
   `python3 lib/counters.py` пересчитывает `n/m` в roadmap; коммит
   `docs(план): EXX-SYY закрыт — n/m`. Круг на паузе — пункт пропустить.
6. Ветка задачи: `python3 lib/экран_выхода.py --вливание <круг>`; первая
   строка ответа решает:
   - `main` — задачи нет, пункт пропустить (как раньше);
   - `пауза` — круг не закрыт: всё уже закоммичено в ветку, вопроса про
     main нет, остаёшься в ветке;
   - `вопрос` — круг закрыт: **единственный вопрос хвоста** «влить в main?».
     «Да» → `python3 lib/экран_выхода.py --вливание <круг> --да` (внутри
     `lib/ветка_задачи.py влить`: `merge --no-ff`, ветка удаляется). Код 2 →
     одна строка с причиной, ветка не тронута, остаёшься в ней. «Нет» —
     остаёшься в ветке.
   Вливать только после п. 3–5: рабочая копия должна быть чистой.
7. `python3 lib/уборка.py` — сносит только влитые дорожки.
8. `python3 lib/экран_старта.py --снять <круг>`.

Затем один экран: итог, хеши коммитов, что снесено, что осталось чужим и
где ты остался — последняя строка `остался:` из `--вливание` (main или ветка
задачи).
Последняя строка сессии — команда следующей сессии в блоке кода:
круг не закрыт → `/plexus:start <id круга>`; закрыт → следующий этап из
`python3 lib/counters.py` (`/plexus:start EXX-SYY`).

## Никогда

- Не спрашивать разрешения на очевидные шаги хвоста (§8) — делать.
- Не пушить.
- Не удалять невлитые дорожки.
- Не доделывать за работника упавшую задачу.
- Не писать в итог цифры, которых не дал скрипт.
- Не архивировать круг, в котором остались ✗ или ✋.
- Не удалять устаревшие заметки без «да».
