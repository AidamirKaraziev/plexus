# Заводим проект

A one-off operation and the entry point to every other skill. Without it
`/plexus:note` finds no vault and stop; `/plexus:roadmap` and `/plexus:status` find
no roadmap. This skill creates both halves at once.

Three screens of interview, then everything is written in one go. Speak Russian
to the user throughout; the files are Russian too.

## Порядок

### 0. Проверить, что не сделано раньше

```
git rev-parse --show-toplevel
python3 ${CLAUDE_PLUGIN_ROOT}/lib/vault.py --check
ls .claude/plan/roadmap.md
ls .git/hooks/post-commit
git check-attr merge .claude/ledger.jsonl <vault>/проект.md
```

`<vault>` — путь из ответа сторожа: база не обязана лежать в `vault/`.

Смотреть сверху вниз, первый подходящий пункт — ответ:

- Всё есть: сторож `ок`, roadmap, хук, оба `union` — одна строка
  «`<проект>` уже заведён — делать нечего». Стоп, ничего не писать.
- Половина есть, половины нет — достроить недостающее, интервью пропустить в
  той части, ответ на которую уже лежит в файлах.
- Не репозиторий — предложить `git init` и подождать «да». Без git не работает
  хук и не будет истории плана.

### 1. Дешёвый взгляд на репозиторий

Только чтобы вопросы были про этот проект, а не вообще. Потолок — три команды,
и ни одного файла кода:

```
ls
head -30 README.md 2>/dev/null
head -20 CLAUDE.md 2>/dev/null
```

Пусто — ничего страшного, спрашиваем всё у человека.

### 2. Экран первый: контекст

Один вызов `AskUserQuestion`, три вопроса. Варианты ответов формулировать под
то, что видно в репозитории.

1. Что за продукт и для кого — одной фразой.
2. Стадия: идея · первые пользователи · растём · поддерживаем.
3. Что мешает прямо сейчас сильнее всего.

### 3. Экран второй: папки

Предложить **пять-семь русских папок** под этот проект и дать утвердить.
Названия — из ответов первого экрана, а не из общего списка. Продукт про
деньги — появится `деньги/`; много внешних сервисов — `интеграции/`.

Три папки берутся почти всегда, потому что на них держится `/plexus:note`:

| Папка | Что туда |
|---|---|
| `решения/` | выбрали один вариант из нескольких, есть отклонённая альтернатива |
| `баги/` | причина оказалась не там, где симптом |
| `приёмы/` | техника, которая повторится в других местах |

Остальные — под проект: `архитектура/`, `интеграции/`, `деньги/`, `продукт/`,
`эксперименты/`. Больше семи не предлагать: папка, в которую за полгода легло
две заметки, только мешает выбирать.

Человек утверждает, переименовывает или выкидывает. Пишем ровно то, что он
утвердил.

### 4. Экран третий: первые эпики

Пять-девять эпиков и раскладка по `Сейчас` (один-два) / `Дальше` (два-три) /
`Потом` (остальные). Эпик — результат для человека, который пользуется
продуктом, а не слой системы: «дарение без трения», не «доработать API».

Показать списком и дождаться «да». Этапы **не** нарезать — это `/plexus:roadmap E01`.

### 5. Записать всё разом

```
mkdir -p vault .claude/plan/archive
mkdir -p vault/<каждая утверждённая папка>
touch .claude/ledger.jsonl
```

Файлы — по шаблонам ниже: `vault/проект.md`,
`vault/карта.md` (образец — `${CLAUDE_PLUGIN_ROOT}/lib/карта-образец.md`),
`.claude/plan/roadmap.md`.

Хук, дописывающий хеш коммита в последнюю строку ledger, — копия шаблона
из плагина:

```
cp "${CLAUDE_PLUGIN_ROOT}/lib/post-commit" .git/hooks/post-commit
chmod +x .git/hooks/post-commit
```

Хук уже есть — не трогать. Проверить `.gitignore`: `.claude/` и `vault/` не
должны быть в игноре целиком, иначе у плана и базы не будет истории. В игноре —
сказать человеку, самому не править.

**Склейка.** Две сессии пишут в ledger и `проект.md` одновременно, поэтому git
должен склеивать их, а не конфликтовать. Дописать только те строки, которых ещё
нет — файла нет, он просто создаётся; `<vault>` — путь из ответа сторожа:

```
for l in '.claude/ledger.jsonl merge=union' '<vault>/проект.md merge=union'; do
  grep -qxF -- "$l" .gitattributes 2>/dev/null || printf '%s\n' "$l" >> .gitattributes
done
```

Файл без перевода строки в конце склеит последнюю строку с первой новой —
перед дописыванием проверить `tail -c1`, при нужде сначала `printf '\n' >>`.
Проверить: `git check-attr merge .claude/ledger.jsonl` → `union`.

### 6. Проверить своей же работой

```
python3 ${CLAUDE_PLUGIN_ROOT}/lib/vault.py
```

Сторож должен ответить путём и списком папок. Ответил отказом — чинить сразу,
а не сообщать об успехе.

### 7. Экран итога

Один блок моноширинного текста: дерево созданного и что делать дальше. Без
прозы вокруг.

```
ASTRA заведён

  vault/проект.md            карта проекта — открой и прочитай
  vault/карта.md             куда что класть
  vault/решения/ баги/ приёмы/ интеграции/
  .claude/plan/roadmap.md    5 эпиков: 2 сейчас, 3 дальше
  .claude/ledger.jsonl       учёт пуст
  .gitattributes             union: ledger, проект.md
  .git/hooks/post-commit     хеши дописываются сами

ДАЛЬШЕ  /plexus:roadmap E01     нарезать первый эпик на этапы
        /plexus:start        начать работу
```

## Шаблон vault/проект.md

Этот файл человек открывает в редакторе и сразу понимает, о чём проект и куда
что класть. Поэтому он карта, а не оглавление.

```markdown
---
проект: <имя папки репозитория>
обновлён: <YYYY-MM-DD>
---

# <Проект>

<Одна фраза: что за продукт и для кого.>

Стадия: <из первого экрана>
Сейчас мешает: <из первого экрана>

## Где что лежит

- `решения/` — <что туда>
- `баги/` — <что туда>
- …

Полный контракт — в `карта.md`. План и учёт живут отдельно, в `.claude/`.

## Заметки

Списки пополняет `/plexus:note`. Пока пусто.
```

## Никогда

- Ничего не коммитить.
- Не запускать интервью там, где сторож уже ответил `ок`.
- Не перезаписывать существующие `roadmap.md`, `ledger.jsonl`, `проект.md`,
  `карта.md` — только достраивать недостающее. `.gitattributes` и `.gitignore`
  — только дописывать строки, которых нет.
- Не читать код проекта: три команды из шага 1 — потолок.
- Не нарезать эпики на этапы и не придумывать этапы самому.
- Не создавать больше семи папок и не заводить папку «разное».
- Не писать ничего за пределами текущего репозитория.
