# Круг — задание, которое человек утверждает один раз

Человек включается **один раз, перед началом**, отдаёт всю информацию и
дальше не участвует до итога. Это работает только если задание полное:
что не написано — не существует. Поэтому интервью здесь не вежливость,
а несущая конструкция. Цена платится один раз, в начале.

Speak Russian to the user throughout.

До «утверждаю» скилл **только собирает задание**: не трогает код, не
запускает агентов, ничего не коммитит. После «утверждаю» он ведёт работу
по файлу — раздаёт задачи работникам и показывает итог (§7). Коммитит
по-прежнему человек.

## 1. Что человек уже сказал

Взять формулировку из вызова: `/plexus:task добавить фильтр в список заявок`.
Пусто → один вопрос в чат: «Что делаем?» — и ждать.

Дальше прочитать **только то, что нужно для вопросов**: план этапа, если
задача из плана; файлы, названные человеком. Не читать базу знаний
целиком, не обходить репозиторий — на этом шаге дорог не контекст, а
ясность.

## 2. Интервью до 100 %

«Уверенности на 100 %» у модели не бывает. Её заменяет правило: **всё,
чего не хватает для исполняемого критерия, спрашивается сейчас.**

Спрашивать про то, без чего нельзя написать задачу:

- **Граница** — что входит и, главное, что **не** входит.
- **Критерий** — по чему человек поймёт, что готово. Не «работает
  фильтр», а что он увидит или какая команда позеленеет.
- **Проверка** — какой командой это гоняется. Команды нет — так и
  сказать, задача пойдёт с `проверка: человек`.
- **Развилки** — там, где вариантов больше одного, и выбор меняет работу.
- **Запреты** — файлы и области, куда нельзя.

Не спрашивать: то, что видно в коде; значения по умолчанию; косметику;
то, что человек уже сказал. Вопрос, ответ на который есть в репозитории, —
это не интервью, это перекладывание работы.

**Как спрашивать.** AskUserQuestion, до четырёх вопросов **одним раундом**,
с готовыми вариантами и коротким «чем отличается» в описании каждого.
Свой вариант человек допишет сам. Раундов не больше двух: если после
второго что-то всё ещё неясно — это не вопрос, а решение, которое человек
не готов принять; вынести его в «Решено до старта» как явное «решаем по
ходу, спросить менеджера» и идти дальше.

Ответ понят наполовину → переспросить. **Догадка запрещена, даже
разумная.**

**Вопрос вернули: «посоветуй, что лучше».** Это не отказ отвечать, а
просьба о работе, которую должен был сделать ты. Дать рекомендацию первой
строкой, под ней коротко «за» и «против» каждого варианта и чем платим за
выбранный, — и задать вопрос ещё раз. Раунд на это не тратится. Молча
выбрать за человека нельзя: развилку он вынес сюда не случайно.

## 3. Критерий должен быть исполняемым

Каждая задача проверяется тем, что можно выполнить и увидеть результат.
Прогнать глазами по трём вопросам — критерий не проходит, если хоть один
без ответа:

| Вопрос | Плохо | Хорошо |
|---|---|---|
| Кто проверяет? | «код работает» | `pytest tests/api/test_filter.py` |
| Что увидит? | «фильтр готов» | «в списке заявок выпадашка «Статус», выбор оставляет только свои» |
| Когда неверно? | — | «пустой выбор → показаны все, не ноль» |

Критерий не сводится к команде (дизайн, текст, формулировка) →
`проверка: человек`. Это законный вид задачи, а не недоделка: в экране
круга она идёт с ✋ прямо к человеку.

**Дизайн — отдельная задача, и раньше кода.** Утверждённого макета нет →
первая задача его рисует, с `проверка: человек`; задача с логикой идёт
следующей и опирается на утверждённый. Смешивать рисование с кодом
нельзя: правка по макету тогда тащит за собой весь контекст реализации и
круг оплачивает его дважды.

**Размер задачи меряется контекстом, не часами.** Резать так, чтобы
работник уложился в 200–250k токенов — четверть окна. Заведомо не влезает
→ делить. Своего счётчика у субагента нет, поэтому защита здесь, на
нарезке; фактический расход экран круга показывает уже постфактум, как
сигнал «в следующий раз резать мельче».

## 4. Файл задания

Имя — **по смыслу, без идентификаторов**: `фильтр в списке заявок.md`, а
не `E06-S02.md`. Имя занято → уточнить имя, не вешать число.

Путь: `круги/<имя>.md` внутри vault — файл читает человек, значит он в vault.
Каталога нет → создать. Закрытые круги уезжают в `архив/` внутри `круги/`.

```markdown
---
этап: E06-S02          # id только здесь, для машины; нет плана — строку убрать
статус: черновик
---

# Фильтр в списке заявок

Цель: оператор видит только свои заявки, не листая весь список.
Готово, когда: `make test` зелёный, в списке заявок работает выбор «Мои».

## Решено до старта
- Фильтр в URL, не в localStorage — ссылку надо пересылать коллеге.

## Не трогаем
- экспорт в CSV, схему таблицы requests

## Задачи

### Параметр фильтра в API
кому: работник бэк · файлы: api/requests.py
готово, когда: GET /api/requests?mine=1 отдаёт только заявки текущего оператора
проверка: pytest tests/api/test_requests.py

### Выпадашка в списке · после «Параметр фильтра в API»
кому: работник фронт · файлы: ui/requests/List.tsx
готово, когда: выбор «Мои» перезагружает список и остаётся в URL
проверка: npm test -- List
```

Обязательное:

- **Цель** и **«готово, когда»** на весь круг — одной проверяемой фразой.
- **Задач не меньше двух.** Одна задача — это не круг, это правка: сказать
  об этом человеку и предложить сделать её обычным порядком.
- Каждая задача: имя по смыслу · `кому` (роль) · `файлы` · `готово,
  когда` · `проверка`. Зависимость — `· после «имя задачи»` в заголовке.
- **Не трогаем** — файлы и области, закрытые для работников. Пусто →
  спросить: пустой раздел означает «можно везде».
- Две задачи не делят один файл. Делят → либо объединить их в одну, либо
  развести по файлам; параллельные работники не правят одно и то же.
- **Проверка задачи не опирается на то, чего ещё нет.** Команда в
  `проверка:` гоняет файл, который делает эта же задача или задача
  раньше неё. Опирается на более позднюю — порядок задач переставить.
  Проверить глазами перед показом: пройти задачи сверху вниз и для
  каждой спросить, существует ли уже всё, что названо в `проверка:`.

## 5. Решения — заметками в vault

Ответ из интервью становится заметкой, если верно (а) или (б), и всегда (в):

- (а) выбирали между двумя и более вариантами;
- (б) ответа нет в коде и плане — пришлось спросить человека;
- (в) повлияет на следующие задачи, а не разовая настройка.

Не заметка: значение по умолчанию, очевидное из кода, косметика.

Такие ответы идут **и** в «Решено до старта» (коротко, для работников),
**и** отдельной заметкой в `vault/решения/` или в тематическую папку —
одна заметка на одно решение, с причиной «почему так, а не иначе». Формат
и строка в `проект.md` — как в `/plexus:note`.

## 6. Показать и утвердить

Напечатать в чат само задание — целиком, как оно легло в файл, без
пересказа. Под ним одна строка:

```
Утверждаешь? «утверждаю» — или скажи, что поправить.
```

Правка — переписать файл и показать снова. Спорить с правкой нельзя;
можно один раз назвать цену («уберём проверку — итог придётся смотреть
руками»), дальше выполнять.

«Утверждаю» → `статус: утверждено <дата>` в frontmatter, строка в
`.claude/ledger.jsonl` о начале круга (учёт задним числом не
восстанавливается — размечать с первой минуты, а не с первого коммита) и
одна строка в чат: путь к файлу и сколько в нём задач. На этом скилл
заканчивается.

## 7. Работа по кругу

Начинается сразу после «утверждаю» и идёт без человека до итога.

**Очередь.** Задача закрыта, если она есть строкой в разделе «Итог»
файла круга. Берётся первая незакрытая, у которой закрыты все её
`после «…»`. Независимые друг от друга задачи можно запустить одним
блоком — файлы у них не пересекаются по правилу §4.

**Запуск.** `Agent` с `subagent_type: "plexus:programmer"` и
`isolation: "worktree"`. Дорожку и ветку заводит сам механизм субагента —
человек их не видит и в main остаётся. В промпт кладётся **только**:
текст задачи целиком, разделы «Решено до старта» и «Не трогаем», путь к
файлу круга. База знаний не кладётся и работником не читается.

**Приёмка отчёта.** Отчёт работника сохраняется в
`.claude/отчёты/<круг>/<задача>.md` и прогоняется:

```
python3 ${CLAUDE_PLUGIN_ROOT}/lib/отчёт.py <отчёт> --круг <файл круга> --задача «<имя>»
```

Не прошёл — вернуть работнику один раз, с текстом того, что не сошлось.
Не прошёл повторно — ✗ на экран, дальше не чинить. Команда проверки
упала (`3 failed`) — это честный ✗, а не повод доделывать за работника:
ревью и доделки — не этот шаг.

**По ходу** — одна строка в чат на задачу, чтобы человек не ждал вслепую:

```
✓ Проверка отчёта работника · 0.4 ч · 180k · 18%
```

**Цифры** берёт `python3 ${CLAUDE_PLUGIN_ROOT}/lib/spend.py --json` по ветке
работника; окно — доля от окна его модели, ⚠ при больше 25 %. Данных по
ветке нет — в колонках «—». Выдумывать расход нельзя, и у работника его
не спрашивают: в отчёте таких полей нет.

**Итог.** Экран целиком — в чат и тем же текстом в раздел «Итог» файла
круга. Успешная задача — одна строка; разворачиваются только ✗ и ⚠.
Последняя строка — текст коммита, чтобы человек не зависал на полпути.

```
КРУГ  <имя круга>                                  5 задач · 4 ✓ · 1 ✗

     задача                        время  токены  окно  проверка
  ✓  Проверка отчёта работника      0.4 ч   180k   18%  ок
  ✓  Роль работника                 0.2 ч    90k    9%  ок
  ✓  Запуск работника из круга      0.9 ч   240k   24%  ✋ человек
  ✓  Уборка дорожек                 0.3 ч   120k   12%  ок
  ✗  Обкатка на Astra               0.6 ч   310k   31%  make test → 3 failed
                                   ─────  ──────
                                    2.4 ч   940k

  ✗  Обкатка: фикстура БД не поднимается в worktree — нужен ты
  ⚠  Обкатка вышла за 25% окна — в следующий раз резать

  КОММИТ  feat(круг): работник делает задачу сам и отчитывается
```

## Никогда

- Не догадываться. Неясно — стоп и вопрос, даже если догадка разумная.
- Не писать задачу без исполняемого критерия и без `проверка:`.
- Не заводить ветки и дорожки руками. Человек всегда в main; дорожку
  работника заводит `isolation: "worktree"` — невидимо для человека.
- До «утверждаю» не запускать агентов и не писать код. Даже «раз уж мы
  тут». После — работу делают работники, а не ты: свой код в задачах
  круга ты не пишешь и за работника не доделываешь.
- Не коммитить. Файл задания коммитит человек, когда захочет.
- Не класть файл круга в `.claude/` — он для человека, значит в `vault/`.
- Не называть файлы и задачи идентификаторами. `E0N-S0M` живёт только во
  frontmatter.
- Не расширять задание за то, что человек утвердил. Появилось нужное и
  соседнее — отдельной строкой в «Решено до старта», не новой задачей.
