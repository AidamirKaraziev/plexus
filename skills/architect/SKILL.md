# Архитектор — фундамент проекта

Фундамент — 20 % работы, важные на 80 %: верхнюю функцию перепишем в любой
момент, кривые границы модулей — нет. Скилл находит, что не так, человек
решает, знания ложатся в базу, код делают работники кругами.

Speak Russian to the user throughout.

Корень Плексуса — `${CLAUDE_PLUGIN_ROOT}`; в Codex эта строка не раскрывается — бери путь из строки контекста «корень Плексуса: …», а если её нет — папку на два уровня выше этого SKILL.md.

**Кто что делает.** Агенты `architect` только читают и запускают
анализаторы. Скилл показывает и спрашивает; после «да» человека пишет
**только знания и правила**: vault, AGENTS.md / CLAUDE.md, план. Конфиги
линтеров, команда проверки, эталонный модуль, рефакторинг — задачи кругов
для `programmer`. Ничего не коммитит.

**Режимы.** `/plexus:architect` — фундамент (этот файл). `module <имя>` и
`audit` ещё не готовы: скажи об этом человеку одной строкой и предложи
фундамент.

## 1. Что уже есть

Прочитать **только**:

- `vault/проект.md` — стадия, что мешает, заметки про архитектуру;
- `vault/архитектура/аудит *.md` — прошлый аудит есть → сказать дату и
  балл и спросить: повторить с нуля или продолжить план фундамента;
- карту репозитория: `git ls-files | awk -F/ '{print $1"/"$2}' | sort | uniq -c | sort -rn | head -40`;
- маркеры стека: `go.mod`, `package.json` (есть ли react), `Cargo.toml`
  / `src-tauri`, папки миграций `*.sql`.

Код не читать — это работа агентов.

## 2. Интервью — один раунд

AskUserQuestion (в Codex — `request_user_input`; недоступен — один вопрос
текстом с вариантами), до четырёх вопросов одним раундом. Спрашивать
только то, чего нет в `проект.md`:

- **Что болит** — где сейчас тратится больше всего времени или ломается.
- **Что заморожено** — решения, которые аудит не пересматривает.
- **Как делится команда** — кто какой модуль берёт (влияет на границы).
- **Внешние ограничения** — сертифицированная ОС, ГИС, офлайн, железо.

Ответ уже есть в базе — не спрашивать. Ответ понят наполовину —
переспросить; догадка запрещена.

## 3. Области и запуск агентов

Области — по маркерам стека; каждой — свои чек-листы из
`<корень Плексуса>/skills/architect/checklists/` плюс `общее.md`:

| область | папки | чек-листы |
|---|---|---|
| бэкенд | код сервера без миграций | go.md |
| фронт | приложение на React | react-ts.md |
| desktop | src-tauri, нативная оболочка | rust-tauri.md |
| БД | миграции, схема, реестр владения | postgres.md |
| безопасность | весь репозиторий: конфиги, зависимости, секреты, логи | безопасность.md |
| база знаний | всё вне `vault/`: docs, README, AGENTS.md, CLAUDE.md, правила в корне | — |

Стека нет в таблице — область всё равно заводится, только с `общее.md`,
и человеку говорится, что чек-листа под стек нет. Область больше ~600
файлов — делится на подобласти по верхним папкам, агент на каждую.

**Правила проекта** для каждого агента: ADR, правила в корне,
`AGENTS.md`, заметки `vault/архитектура/` и `vault/решения/`, ответы
интервью. Пути — списком, агент читает сам.

**Запуск — все области одним сообщением, параллельно.**
В Claude: `Agent` с `subagent_type: "plexus:architect"`, без `isolation` —
агент ничего не пишет. В Codex: обычный субагент, в его задание кладётся
**текст `<корень Плексуса>/agents/architect.md` целиком** (frontmatter
можно опустить), затем задание.

Задание агенту — ровно это:

```
режим: аудит
область: <имя> — <абсолютные пути>; не входит: <пути соседних областей>
чек-листы: <абсолютные пути>
правила проекта: <абсолютные пути>
инструменты на машине: <какие анализаторы стоят — `command -v …`>; не ставить
ответы человека: <что болит, что заморожено, как делится команда, ограничения>
Финальный ответ — только отчёт в формате режима «аудит».
```

Пока агенты работают — одна строка: «Аудит идёт: N областей
параллельно, это 5–10 минут».

## 4. Приёмка отчётов

Каждый отчёт сохранить в `.claude/отчёты/архитектор/<дата>/<область>.md`
и прогнать:

```
python3 <корень Плексуса>/lib/находки.py <отчёт>
```

Не прошёл — вернуть агенту один раз с текстом ошибки. Не прошёл повторно —
область в сводке со знаком ✗ и причиной; чинить за агента нельзя.

## 5. Сводка — один экран

```
Аудит <проект> · <дата> · областей N

область        балл  критично  важно  мелочь
бэкенд         1/5   3         10     4
…

Критичное (до 7, по всем областям):
1. <суть> — <область>, <где>, объём <S/M/L>
…
Спорных решений: N · документов вне vault: N (перенести K, в архив M)
```

Повторы между областями (одно правило нарушено и в бэкенде, и в БД)
сводить в одну строку с обеими областями.

## 6. Решения — по одному

**Спорное** — каждый пункт отдельным вопросом AskUserQuestion: варианты
агента с процентами пользы и недостатков, совет агента первым вариантом
с пометкой (Recommended). Решение человека — строкой в память шага.

**Документы вне vault** — показать две группы:

- перенести (польза есть): путь → заметка vault, нужен ли перевод;
- в архив удалённых (мусор или мешает работе через Плексус): путь → почему.

Одним вопросом: «одобряю всё / одобряю с исключениями / разберу по
одному». Без одобрения ничего не удаляется.

**Недостающие правила** — списком; человек вычёркивает лишнее.

## 7. Запись — после «да»

Показать список файлов, которые будут созданы, изменены и удалены, и
спросить «записываю?». После «да», по порядку:

1. **Аудит** — `vault/архитектура/аудит <ГГГГ-ММ-ДД>.md`, шапка
   `статус: утверждён`: сводка из §5, все находки по областям, решения по
   спорному, ссылки на ADR. По этому файлу `/plexus:start` понимает, что
   фундамент заложен.
2. **ADR** — каждое решение по спорному и каждое новое правило уровня
   архитектуры: заметка в `vault/решения/` по-русски — контекст, решение,
   отклонённое с процентами, цена.
3. **Перенос знаний** — документ за документом: заметка по-русски в нашем
   формате → строка в `проект.md` → удаление старого файла. Ссылки на
   старый путь в коде и документах — заменить на заметку.
4. **Архив удалённых** — `vault/архив удалённых/<старый путь>.md`: шапка
   (откуда, когда, почему удалён), затем исходный текст как есть. Потом
   удалить оригинал.
5. **Правила для агентов** — в корне и в папке каждой области `AGENTS.md`
   на 10–30 строк: правило одной строкой + ссылка на заметку vault, где
   «почему». Знаний внутри нет. Рядом `CLAUDE.md` из одной строки
   `@AGENTS.md`. Существующий `CLAUDE.md` с содержимым — его знания уходят
   в vault по п. 3, правила — в `AGENTS.md`; перезапись — только после «да».
6. **План** — эпик «Фундамент» в `.claude/plan/` проекта: строка в
   `roadmap.md` и файл эпика в формате `/plexus:roadmap`. Порядок этапов:
   1. команда проверки, lefthook, конфиги линтеров — барьеры раньше
      правок, чтобы каждая следующая правка проверялась машиной;
   2. эталонный модуль и шаблон нового модуля;
   3. критичные находки;
   4. важные находки, по областям;
   5. мелочи — одним этапом в конце.

   Этап — на одну сессию; у каждого «готово, когда» и команда проверки.

Новая папка в vault (`архитектура/`, `архив удалённых/`) — строкой в
`vault/карта.md` и в «Где что лежит» `проект.md`.

## 8. Итог

```
Фундамент заложен · аудит vault/архитектура/аудит <дата>.md
ADR: N · перенесено: K · в архиве: M · AGENTS.md: P папок
План: эпик «Фундамент», этапов S — первый: <имя>
Дальше: /plexus:task <первый этап>
```

Текст коммита не пишет — это `/plexus:close` или `/plexus:commit-message`.

## Нельзя

- Писать код, конфиги линтеров, скрипты — это задачи кругов.
- Удалять или перезаписывать без «да» человека.
- Чинить отчёт агента за него или дописывать находки «от себя».
- Читать код проекта самому вместо агентов — контекст скилла для решений.
- Коммитить.
