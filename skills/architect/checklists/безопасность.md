# Безопасность, логи и профилирование — поперёк стеков

Уточняет `общее.md`. Формат правила: заголовок — суть; нельзя → надо;
источник; проверка; тяжесть по умолчанию. Базовая рамка — OWASP ASVS.

## Секреты

### Секретов нет в репозитории и в истории
- нельзя: `.env с паролем в git; ключ в коде; «удалили следующим коммитом»`
- надо: `.env.example без значений; секреты из окружения или хранилища; утёкший — сменить`
- источник: [OWASP — Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)
- проверка: `gitleaks git` (вся история) и `gitleaks protect --staged` в pre-commit
- тяжесть: критично

## Зависимости

### Уязвимости зависимостей проверяются на каждом изменении
- нельзя: `проверка «когда-нибудь»`
- надо: `osv-scanner по всем lock-файлам + govulncheck / cargo deny в команде проверки`
- источник: [OSV-Scanner](https://google.github.io/osv-scanner/)
- проверка: `osv-scanner scan -r .`
- тяжесть: важно

## Код

### Статический анализ безопасности включён
- нельзя: `только ручное ревью`
- надо: `gosec (через golangci-lint), semgrep с наборами под стек`
- источник: [Semgrep — Rules](https://semgrep.dev/docs/writing-rules/overview)
- проверка: `semgrep scan --config auto --error`
- тяжесть: важно

### Ввод проверяется на сервере по белому списку
- нельзя: `доверять проверке на фронте`
- надо: `схема / валидатор на границе API: типы, диапазоны, длины`
- источник: [OWASP — Input Validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html)
- проверка: агент
- тяжесть: критично

### Права проверяются на сервере в каждом сценарии
- нельзя: `кнопка скрыта на фронте — значит запрещено`
- надо: `сервис проверяет право пользователя на объект (учреждение, документ) до действия`
- источник: [OWASP Top 10 — A01 Broken Access Control](https://owasp.org/Top10/A01_2021-Broken_Access_Control/)
- проверка: агент + тест «чужой пользователь получает отказ»
- тяжесть: критично

### Пароли — только медленным хешем
- нельзя: `sha256(password); пароль в логе`
- надо: `argon2id или bcrypt с солью`
- источник: [OWASP — Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- проверка: агент
- тяжесть: критично

### Ошибка наружу не раскрывает внутренности
- нельзя: `ответ API с текстом SQL-ошибки или стеком`
- надо: `пользователю — код и понятное сообщение; детали — в лог с id запроса`
- источник: [OWASP — Error Handling](https://cheatsheetseries.owasp.org/cheatsheets/Error_Handling_Cheat_Sheet.html)
- проверка: агент
- тяжесть: важно

## Логи и аудит

### Аудит отдельно от технических логов
- нельзя: `«кто провёл документ» ищем в общем логе приложения`
- надо: `журнал аудита — отдельная таблица / поток: кто, что, когда, над чем; не удаляется приложением`
- источник: [OWASP — Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
- проверка: агент
- тяжесть: важно

### Логи структурные и связаны id запроса
- нельзя: `строки без полей; нельзя собрать путь одного запроса`
- надо: `JSON-лог с request_id / trace_id, уровнем, модулем`
- источник: [OpenTelemetry — Logs](https://opentelemetry.io/docs/concepts/signals/logs/)
- проверка: агент
- тяжесть: важно

### В логах нет секретов и персональных данных
- нельзя: `log("login", "password", p); полный номер паспорта / СНИЛС`
- надо: `маскирование на уровне логгера; перечень запрещённых полей`
- источник: [OWASP — Logging: Data to exclude](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude)
- проверка: агент (grep полей password/token/secret в вызовах логгера)
- тяжесть: критично

## Профилирование и наблюдаемость

### Есть способ снять профиль на работающем сервере безопасно
- нельзя: `профилировщик открыт наружу или его нет вовсе`
- надо: `pprof / аналог на localhost за флагом; инструкция «как снять профиль» в базе знаний`
- источник: [Go — Diagnostics](https://go.dev/doc/diagnostics)
- проверка: агент
- тяжесть: важно

### Ключевые операции измеряются
- нельзя: `о медленной проводке узнаём от пользователя`
- надо: `метрики длительности и ошибок по сценариям (Prometheus / OpenTelemetry)`
- источник: [OpenTelemetry — Metrics](https://opentelemetry.io/docs/concepts/signals/metrics/)
- проверка: агент
- тяжесть: мелочь

## Процесс

### Проверки безопасности — в той же команде проверки
- нельзя: `отдельный ручной «аудит перед релизом»`
- надо: `gitleaks, osv-scanner, semgrep в команде проверки; находки по приоритету`
- источник: [OWASP — DevSecOps Guideline](https://owasp.org/www-project-devsecops-guideline/)
- проверка: команда проверки
- тяжесть: важно
