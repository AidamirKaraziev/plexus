# Аналитик — учится на сессиях, сам ничего не решает

Паттерн подтверждается ростом счётчика по прогонам, не одним прогоном.
Скилл копит находки, показывает их человеку и отдаёт одобренное в план —
дальше работает обычный `/plexus:task`, особого пути у аналитика нет.

Speak Russian to the user throughout.

Корень Плексуса — `${CLAUDE_PLUGIN_ROOT}`; в Codex эта строка не раскрывается — бери путь из строки контекста «корень Плексуса: …», а если её нет — папку на два уровня выше этого SKILL.md.

## 1. Гипотеза человека — необязательно

Одна строка в чат, свободный ответ, не `AskUserQuestion` (в Codex — не `request_user_input`):

```
Что скажешь сам? — что нравится, что нет, чем часто пользуешься.
```

Ответ пуст (человек промолчал или ответил «нет») → раздела «Гипотезы
человека» в промпте субагента просто нет. Ответ есть → идёт дословно,
отдельным разделом «Гипотезы человека», без пересказа и без собственной
оценки: для аналитика это гипотеза, а не факт, и он обязан проверить её
счётчиком, а не поверить на слово.

## 2. Свод

```
cd "${CLAUDE_PLUGIN_ROOT}/lib" && python3 аналитика.py --свод
```

Последняя строка вывода — честный размер выжимки в токенах, запомнить
число для итогового расхода (шаг 6). Скрипт сам продвигает курсор и уже
развёл приватность: из личных проектов в выжимке только метрики, текст
реплик — только из проектов разработки. Свод сырьё не пересказывает и
скилл его не редактирует — весь вывод идёт в промпт субагента как есть.

## 3. Запуск аналитика

`Agent`, `subagent_type: "plexus:analyst"`, без `isolation` — правок в файлы
нет, ветка не нужна. Вызывать в foreground: следующий шаг (наблюдения)
зависит от ответа. В Codex — обычный субагент, в задание которого
кладётся текст `<корень Плексуса>/agents/analyst.md` целиком; дорожка не
нужна (правок в файлы нет). В промпт — ровно три части:

1. свод целиком (шаг 2);
2. раздел «Гипотезы человека», если он был (шаг 1);
3. одна строка задачи: найти паттерны, на каждый — адрес (файл скилла,
   строка/раздел) и доказательство (счётчик встреч + сессии);
4. полный путь к `аналитика.py` — `${CLAUDE_PLUGIN_ROOT}` плюс `lib`, уже
   раскрытый в абсолютный: в проекте пользователя `lib/` нет, а работник запускает
   `аналитика.py --свод` по этому пути, а не по относительному.

Сырьё скилл не подбирает и не отправляет — точечные куски по указателям
свода роль запрашивает сама через свои Bash/Grep. Бюджет прогона — 40k
токенов (выжимка ≤20k, куски ≤15k, роль и задача ~3k); превышение —
сигнал резать свод мельче в следующий раз, а не повод скрывать расход.

## 4. Наблюдения — накопитель, не разовый список

Каждую находку субагента сверить с `наблюдения.md` в папке `аналитика/` базы по
формату, описанному в заголовке файла:

- значение уже есть в файле → счётчик встреч растёт, дата и ссылки на
  сессии дописываются к записи;
- значения ещё нет → новая запись.

Находка без счётчика встреч и без ссылок на сессии не выносится дальше
и человеку не показывается — так держит роль, скилл её только исполняет.

## 5. Показать и спросить

Список предложений — человеку, по формату роли: наблюдение /
доказательство (встречалось N раз · сессии: …) / предложение / куда
именно.

Решение по ним — **одним `AskUserQuestion` с `multiSelect`** (в Codex — `request_user_input`; недоступен — один вопрос текстом с вариантами), а не
построчным «берёшь?» в чат: предложений может быть пять, и пять раундов
вопросов человек не выдержит. Один пункт — одно предложение, в описании
короткое «что изменится». Свободный ввод в вопросе есть сам по себе
(последний пункт «Other»), отдельным вариантом его не заводить.
Предложений больше четырёх — вопрос разбивается на несколько раундов по
четыре, не больше двух раундов за прогон; что не влезло, уходит в
`наблюдения.md` без пометки «отклонено» и придёт в следующий раз.

- «Беру» → строка в `.claude/plan/roadmap.md`, раздел «Дальше», в
  формате соседних строк: `- **E<следующий свободный номер> ·
  <короткое имя>** — <предложение> · 0/0 · skills`. Дальше эту строку
  берёт в работу обычный `/plexus:roadmap` / `/plexus:task` — здесь она просто
  появляется.
- Не «беру» → в `наблюдения.md` у записи ставится «отклонено <дата>»
  (шаг 4), в план ничего не идёт. Отклонённое с той же пометкой второй
  раз в список не выносится, пока не наберёт новых доказательств сверх
  тех, что уже были при отклонении.

Шаг 1 остаётся свободной строкой и вариантов не получает: там нужен
собственный текст человека, а подсказанные варианты подменят его
формулировки моими — ровно то, чего этот круг избегает.

## 6. Расход

Последней строкой в чат — фактический расход прогона: размер выжимки
(шаг 2) плюс расход субагента, который отдаёт харнесс по завершении
вызова `Agent`. Печатать только то, что реально пришло; додумывать
третью цифру нельзя.

## Никогда

- Не коммитить и не заводить ветки — здесь их и не возникает.
- Не править скиллы самому: только адрес в план, саму правку делает
  `/plexus:task` обычным порядком.
- Не читать сырые транскрипты и не пересказывать выжимку своими
  словами — субагент получает её как есть.
- Не выносить предложение без счётчика встреч и ссылок на сессии.
- Не превращать гипотезу человека в единственный источник находок —
  подавать её субагенту как версию для проверки, а не готовый список.
- Не приносить второй раз то, что человек уже отклонил, без новых
  доказательств сверх тех, что были на момент отклонения.
