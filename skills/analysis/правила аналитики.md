# Правила аналитики

Два этапа. ЧТО — аналитика: контекст, сценарии, правила, источники,
входит/не входит, критерии приёмки. КАК — разработка: круг
`/plexus:task` берёт утверждённую аналитику на вход. Пробел из
разработки возвращается вопросом в «Вопросы», в коде не закрывается.

## Путь
`модули/<модуль>/<capability>/аналитика/<файл>.md`. Папки только по
модулям и capability. Роль, автор, дата, тип, этап, статус, youtrack —
в шапке; сводки строит скрипт. Markdown главный, DOCX собирается из
него. Ссылки вики-ссылкой: [[имя файла без .md]].

## Имя и код
`<КОД>-<NN> <что делаем> — <какая проблема>.md`, 2–4 слова на часть.
КОД — кириллическое сокращение capability из её карточки
(`код: МАТДОК`); номер сквозной внутри capability.

## Типы работы
одно слово: `перенос` — перенос на другой стек; `новый` — новый
продукт с нуля; `развитие` — развитие и сопровождение;
`рефакторинг` — рефакторинг. Умолчание — у проекта, эпик переопределяет.

## Статусы
черновик → вычитка → утверждено → в работе → сделано.
отклонено — с причиной. YouTrack зеркалит статус из файла.

## Ворота: два ключа
«утверждено» только когда стоят оба: `верно` — ведущий аналитик,
`понятно` — разработчик («понятно, что делать»). У каждого кто и дата.

## Критерии приёмки
Нумеруются К1, К2…; на них ссылаются задачи круга разработчика.

## Несколько capability
Сценарий через несколько capability — один файл у capability главного
документа. Остальные: поле `затрагивает:` и обратная ссылка в их
`capability.md`, раздел «Меня затрагивают». Исключений нет.

## Папка перенос
`модули/перенос/` — не модуль: там лежат карты переноса аналитики
из чужого источника (`<источник>.json`), сторож её пропускает. Формат
карты и работа скрипта — в `перенос.md` рядом с этим файлом.

## Вход
Карточка `capability.md` — единственный вход в аналитику capability;
ИИ читает её, а не ищет по vault.

## Сторож
```
python3 lib/аналитика_заметки.py <папка модули> [--код <корень>]
python3 lib/аналитика_заметки.py --самопроверка
```
Выход 0 — чисто, 1 — ошибки; каждая строкой `<путь>: <что не так>`.
`--код <корень>` — ещё и что в корне репозитория есть папка
`backend/internal/modules/<en>/<capability>`; без флага код не смотрит.

**Ссылки `[[…]]`** читаются по хвосту пути: `[[x/y]]` — файл, чей путь
кончается на `x/y.md`; голое имя — единственный файл с таким именем.
Ноль совпадений — мёртвая, два и больше — неоднозначная. `|подпись` и
`#раздел` отбрасываются.

**Строгость растёт со статусом:**

| статус | что проверяется сверх предыдущего |
|---|---|
| черновик | форма: путь, имя, шапка, ссылки, карточка, код |
| вычитка | критерии К1…: хоть один, номера подряд, без повторов |
| утверждено, в работе, сделано | ключи `верно` и `понятно`, `кто` и `дата` |
| отклонено | форма и `причина:` в шапке |

Форма на любом статусе включает и значения статуса и типа работы из
списков выше, и обратные ссылки: каждое `затрагивает:` есть в «Меня
затрагивают» карточки, и наоборот; «Своя аналитика» карточки
перечисляет все аналитики capability и только их.

## Пример дерева
```
модули/
  имущество (assets)/
    materialdocuments/
      capability.md
      аналитика/
        МАТДОК-01 списание — расхождение остатков.md
        МАТДОК-02 перенос — потеря партии.md
    contracts/
      capability.md   <- «Меня затрагивают»: [[МАТДОК-02 ...]]
```
Код: backend/internal/modules/assets/materialdocuments.
