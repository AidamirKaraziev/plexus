# Перенос аналитики: карта формата 1

Договор между скиллом аналитики, картой и скриптом `lib/перенос_аналитики.py`.
Чего здесь нет, того скрипт не делает и не угадывает. Образец карты:
`skills/analysis/образец/модули/перенос/образец.json`.

Перенос — это когда аналитика уже написана где-то вне vault (папка
«источник») и её надо разложить по правилам аналитики
(`правила аналитики.md`). Три шага: опись источника → карта (раскладывает
ИИ вместе с человеком) → прогон скрипта. Заготовки получаются со статусом
`черновик`; переписывать их по разделам шаблона — отдельная работа.

## Где лежит карта

`vault/модули/перенос/<источник>.json`, где `<источник>` — короткое имя
латиницей (`zabalans`). Папка `перенос` — не модуль: сторож аналитики её
пропускает целиком. Сам источник в vault не кладут; его корень скрипту
передают аргументом `--источник`.

## Что делает скрипт

```
python3 ${CLAUDE_PLUGIN_ROOT}/lib/перенос_аналитики.py --опись <папка источника> [--метка <метка>] [--выход <json>]
python3 ${CLAUDE_PLUGIN_ROOT}/lib/перенос_аналитики.py --карта <json> --источник <папка> --vault <папка> [--сухой]
python3 ${CLAUDE_PLUGIN_ROOT}/lib/перенос_аналитики.py --самопроверка
```

**`--опись`** пишет каркас карты (в `--выход`, без него — в stdout). Метка
берётся из `--метка`, без неё — «снимок <дата прогона>». В каркасе: `формат`,
`источник`, `шапка аналитики` и `типы файлов` с умолчаниями из этого
файла, пустые `модули`, `capability`, `сценарии`, пустые `не переносится`.
Все файлы источника (кроме `.git/` и `.DS_Store`), по алфавиту путей, лежат
в `не знаю, куда`; у `.md` дописаны `строк` и `заголовки` с номерами строк.
Заголовок — строка, начинающаяся с `#`…`######` и пробела, вне блоков кода.
Раскладывает файлы по сценариям не скрипт, а ИИ в скилле, строка за
строкой.

**`--карта`** применяет карту. Сначала проверяет всё (см. «Коды отказа»),
и только если отказов нет — пишет. С `--сухой` печатает план («создам
карточку …», «создам заготовку …», «перепишу Источник …», «скопирую кадр
…») и не пишет ничего; код выхода тот же, что у настоящего прогона.

**Что пишет прогон:**

1. Для каждой capability из сценариев, у которой нет
   `<vault>/модули/<модуль (en)>/<capability>/capability.md`, — карточку по
   `шаблоны/capability.md`: `модуль`, `capability`, `код`, `путь в коде`
   (`backend/internal/modules/<en>/<capability>`), `владелец таблиц` и
   «За что отвечает» берутся из записи capability в карте. Существующая
   карточка не переписывается; в неё только дописываются недостающие
   ссылки (см. п. 3).
2. Для каждого сценария — заготовку
   `<capability>/аналитика/<код> <название>.md`. Шапка: `код`, `название`,
   `модуль` (полное имя папки из `модули`), `capability`, `затрагивает`
   из сценария; `тип работы`, `этап`, `статус`, `автор`, `роль` из
   `шапка аналитики`; `дата` — дата прогона; `верно`, `понятно`,
   `youtrack`, `круги`, `решения` — пустые, как в шаблоне. Тело — разделы
   `шаблоны/аналитика.md` как есть и последним раздел `## Источник`.
3. Ссылки: в «Своя аналитика» карточки — на каждую заготовку этой
   capability; в «Меня затрагивают» карточки каждой capability из
   `затрагивает` — на заготовку. Недостающие ссылки дописываются, лишних
   не убирают; фраза «Пока нет…» на месте первой ссылки заменяется ею.
4. Кадры и SQL: копии файлов из `кадры` и `sql` сценария в
   `<capability>/аналитика/кадры/` под своим именем файла. Файл с тем же
   именем и тем же содержимым пропускается; с другим содержимым —
   перезаписывается копией из источника.

**Раздел «Источник»** — единственное, что прогон переписывает в уже
существующей заготовке (от строки `## Источник` до следующего `## ` или
конца файла). Остальные разделы и шапку он не трогает. Заготовку находят по
началу имени `<код> ` в папке `аналитика` capability; найдено больше одной —
отказ. Для каждого пункта `источники` в разделе: заголовок
`### <файл>@<метка>, строки a–b` (для файла целиком — `### <файл>@<метка>`),
под ним исходный текст диапазона в блоке ```` ``` ```` (ограда длиннее
самой длинной серии обратных кавычек в тексте). Затем списки в виде
`- кадр: \`кадры/<имя>\``, `- sql: \`кадры/<имя>\``, `- вне источника:
\`<путь из карты>\`` и `- без файла: \`<слово>\``. Поле `спорно` сценария,
если есть, — строкой `Спорная раскладка: …` перед списками.
Повторный прогон на той же карте и том же источнике не меняет ни одного
файла.

## Формат 1: поля карты

Корень — объект. Лишние ключи — отказ (опечатка не должна пройти молча).

| ключ | что это |
|---|---|
| `формат` | число `1`. Другое — выход 1, «формат не поддерживается». |
| `источник` | объект: `метка` (строка; идёт в адреса «Источника»), `дата` (`ГГГГ-ММ-ДД` снимка), `корень` (словами: что за папка; скриптом не читается). |
| `шапка аналитики` | объект «ключ шапки → значение»: `тип работы` (только из списка типов правил аналитики; для переноса — `перенос`), `этап`, `статус` (в этой версии только `черновик`), `автор`, `роль`. |
| `модули` | объект «короткое имя на латинице → имя папки модуля `<рус> (<en>)`». Ключ должен совпадать с `<en>` в значении. |
| `capability` | список записей: `модуль` (ключ из `модули`), `capability` (имя как папка в коде), `код` (кириллица, закреплён навсегда), `название`, `за что отвечает`, `владелец таблиц` (список строк). Пара `модуль`+`capability` не повторяется, `код` на всю карту один. |
| `сценарии` | список записей, см. ниже. |
| `не переносится` | объект: `файлы` (список `{файл, причина}`) и `диапазоны` (список `{файл, строки, заголовок, причина}`). Причина обязательна и непуста. |
| `типы файлов` | объект «расширение без точки, строчными → правило»; правило — `{действие, причина}`, у копируемых ещё `куда`. Ключ `прочие` — правило для расширений, которых нет в таблице. |
| `не знаю, куда` | список файлов, которых ещё не разложили; в каркасе из `--опись` в нём всё, в готовой карте он пуст. |

**Сценарий:**

| ключ | что это |
|---|---|
| `код` | `<КОД>-<NN>`; `КОД` равен `код` его capability, `NN` — две цифры и больше, уникален внутри capability. |
| `название` | `что делаем — какая проблема`, как в имени файла правил аналитики (с « — »). |
| `модуль`, `capability` | куда ложится; пара есть в списке `capability`. |
| `затрагивает` | список имён capability (нужен или пуст); каждая есть в списке `capability`, и не сама эта же. |
| `источники` | список пунктов `{файл}` (файл целиком) или `{файл, строки, заголовок}`. Не пуст. |
| `кадры` | список путей `.png` внутри корня источника (можно пустой). |
| `sql` | то же для `.sql`. |
| `кадры вне источника` | пути, найденные за корнем (`../…`); не копируются, только записываются в «Источник». Необязательно. |
| `ссылки без файла` | слова-ссылки, под которыми файла нет (шаблоны, обрывки имён). Необязательно. |
| `спорно` | строка: почему раскладка сомнительна. Необязательно. |

Все пути в карте — от корня источника (`--источник`), с `/`, без начального
`/`. Любое сравнение путей и заголовков — в нормализации NFC.

## Правила

**Диапазоны строк.** `строки` — `[первая, последняя]`, нумерация с единицы,
обе включаются, `первая ≤ последняя ≤ числа строк файла`. `заголовок` —
точный текст первой строки диапазона (без перевода строки). Если на строке
`строки[0]` стоит не `заголовок`, карта устарела (файл правили): отказ
с кодом 2, в нём называют сценарий (или запись «не переносится»), файл,
ожидаемый и найденный текст. Скрипт заголовок сам не ищет.

**Покрытие `.md`.** Каждый `.md` источника лежит либо в `источники`
сценария, либо в `не переносится.файлы`. Если у файла есть диапазоны (в
сценариях или в `не переносится.диапазоны`), то вместе они покрывают все его
строки без дыр; пересечения разрешены (один раздел может уйти в два
сценария). Файл, указанный в сценарии целиком, покрыт полностью. Дыра —
«не знаю, куда» с номерами строк.

**Остальные файлы** идут по расширению из `типы файлов` (расширение берётся
после последней точки, строчными; нет расширения — `прочие`). Порядок
решения для файла: (1) он в `не переносится.файлы` — не переносится;
(2) он в `источники` сценария — переносится по правилам выше; (3) действие
расширения. Действия: `не переносится` — пропустить; `только по карте` —
если в карте нет, это «не знаю, куда»; `копируется, если назван в тексте
сценария` — копируется, когда он в `кадры`/`sql` сценария, иначе
пропускается; `не знаю, куда` — как раз она. Расширение, которого нет в
таблице, берёт правило `прочие`; нет и `прочие` — «не знаю, куда».

**Кадры и SQL.** Ссылка — слово вида `путь/имя.png` или `путь/имя.sql` (любые
символы кроме пробела, кавычек, скобок и обратных кавычек; расширение без
учёта регистра) в тексте источника сценария, то есть в его диапазоне строк
или во всём файле. Разбор по порядку: (1) путь от папки файла-источника;
(2) путь от корня источника; (3) единственный файл с таким именем во всём
источнике (больше одного — не «единственный», идём дальше). Нашёлся внутри
корня — он обязан стоять в `кадры` (png) или `sql` (sql) этого сценария;
нашёлся вне корня (путь за `..`) — в `кадры вне источника`; не нашёлся —
в `ссылки без файла` (проверка по слову ссылки в тексте). Ссылка, которой
нет ни в одном из трёх списков, — «не знаю, куда». Каждый путь из `кадры` и
`sql` обязан существовать в источнике. Одинаковое имя файла у двух разных
путей в одной capability — отказ (копии лежат в одной папке).

**Сверка перед записью.** Прогон проверяет всё, включая каждый
`заголовок`, раньше, чем создаст хоть один файл; при отказе vault не
меняется.

## Коды отказа

| код | когда |
|---|---|
| 0 | всё разложено (с `--сухой` — план показан, ничего не записано) |
| 1 | неверные аргументы, нет файла или папки, карта не читается как JSON, `формат` не `1`, лишний или потерянный ключ, пустое обязательное поле, повтор `код`, сценарий в неизвестной capability |
| 2 | карта не покрывает источник или устарела; скрипт печатает список строк `<файл>[: строки a–b]: <причина>` и ничего не пишет |

Причины кода 2, по одной строке на каждую: файл источника вне карты («не
знаю, куда»), файл из `не знаю, куда` карты, дыра в покрытии `.md`,
заголовок не на своей строке, диапазон за концом файла, ссылка на кадр или
SQL без места в трёх списках, путь из `кадры`/`sql` или файл из карты, которого
нет в источнике, два разных файла с одним именем в одной capability, больше
одной заготовки с одним кодом в папке.

## После прогона

Сторожем аналитики по `vault/модули` (`правила аналитики.md`, раздел
«Сторож»). Заготовки — форма без смысла: тексты по разделам шаблона
переписывают на финальной версии источника, а не на снимке.
