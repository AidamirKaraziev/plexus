# Аналитика — черновик, который проходит сторожа

Корень Плексуса — `${CLAUDE_PLUGIN_ROOT}`; в Codex эта строка не раскрывается — бери путь из строки контекста «корень Плексуса: …», а если её нет — папку на два уровня выше этого SKILL.md.

Аналитик или разработчик команды говорит, что делаем, — скилл ведёт
интервью, пишет **черновик** и показывает, где он лежит. Граница
скилла — черновик: вычитка, ключи «верно» и «понятно», кадры и сводки — не здесь.

Правила (путь, имя и код, статусы, критерии, сторож) — в
`<корень Плексуса>/skills/analysis/правила аналитики.md`, шаблоны — в
`<корень Плексуса>/skills/analysis/шаблоны/` (`аналитика.md`,
`capability.md`), вопросы — в
`<корень Плексуса>/skills/analysis/интервью по типам.md`. Их текст сюда
не копируется: читай файлы.

Speak Russian to the user throughout; заметки тоже русские.

## Шаги

1. **Тип работы.** Взять из плана:

   ```
   python3 <корень Плексуса>/lib/streams.py --json
   ```

   Поля `тип` и `тип_свой` у нужного эпика: свой `· тип:` в строке
   эпика, иначе `тип:` из шапки `.claude/plan/roadmap.md`. Тип — одно
   слово: `перенос`, `новый`, `развитие`, `рефакторинг`. Типа нет →
   один вопрос с этими четырьмя вариантами. В план скилл ничего не
   пишет: тип заводят init и roadmap.

2. **Где живёт аналитика.** Путь vault даёт
   `python3 <корень Плексуса>/lib/vault.py`; отказ показать человеку
   дословно и остановиться. Затем один вопрос по разделу «До интервью.
   Где живёт аналитика» из `интервью по типам.md` (вопросы не копировать):
   варианты — capability из `vault/модули/` (модуль · capability) и
   «новая capability». Названо в вызове — не спрашивать. Этот шаг не
   раунд интервью. Выбрана существующая — читай её `capability.md`
   (код, путь в коде, «Своя аналитика»), по vault не броди. Новая:
   модуль — существующий или новый (тогда и его `<en>`); английское имя
   capability и код предлагает скилл, человек подтверждает (вариант +
   «Другое»). Код закрепляется навсегда — без «да» не пишется.

3. **Интервью** по `интервью по типам.md`: общий раунд, затем раунд
   под тип из шага 1. AskUserQuestion (в Codex — `request_user_input`;
   недоступен — вопрос текстом с вариантами), до четырёх вопросов за
   раунд, не больше двух раундов. Догадка запрещена, даже разумная.
   Ответа нет — он уходит в «Неизвестное» или «Вопросы» заметки, а не
   выдумывается.

4. **Карточка.** Своей карточки нет — создать `capability.md` по
   шаблону `шаблоны/capability.md` только после «да» на код из шага 2.
   Есть — править в ней только «Своя аналитика» (не «Меня затрагивают»).
   Если сценарий задевает другие capability, перечисли их в
   `затрагивает:` черновика — только те, у которых есть `capability.md`;
   в «Меня затрагивают» каждой из них допиши обратную ссылку на
   черновик. Задетая capability без карточки — строка в «Неизвестное»
   черновика и подсказка завести её отдельным `/plexus:analysis`;
   карточку и код за неё не создавать.

5. **Черновик** по шаблону `шаблоны/аналитика.md`: `статус: черновик`,
   `тип работы:` — слово из шага 1, путь и имя файла — по правилам
   (`модули/<модуль> (<code>)/<capability>/аналитика/<КОД-NN что делаем —
   какая проблема>.md`, номер — следующий сквозной в capability). Каждое
   правило и факт помечены источником; критерии К1, К2… из сценариев.

6. **Сторож:**

   ```
   python3 <корень Плексуса>/lib/аналитика_заметки.py <vault>/модули
   ```

   Не чисто — исправить свои файлы и прогнать снова. Не удаётся
   исправить — показать вывод сторожа дословно.

7. **Ответ** — одна строка: путь к черновику (и к карточке, если
   создана). Без пересказа заметки.

## Режим переноса

Тип `перенос` с исходной аналитикой (папка или файлы старой системы)
идёт вместо шагов 3–5. Договор карты — в
`<корень Плексуса>/skills/analysis/перенос.md`, текст не копируется.
Источник большой: читай каркас описи и нужные куски по номерам строк,
не файлы целиком.

П1. **Опись:**

    python3 <корень Плексуса>/lib/перенос_аналитики.py --опись <источник>

   Это каркас карты; записи «не знаю, куда» в нём — для ИИ.

П2. **Карта.** Разложи каркас по `перенос.md` и сохрани в
   `<vault>/модули/перенос/<источник>.json`. Не знаешь, куда файл или
   заголовок, — оставь в «не знаю, куда», не угадывай.

П3. **Сухой прогон:**

    python3 <корень Плексуса>/lib/перенос_аналитики.py --карта <vault>/модули/перенос/<источник>.json --источник <источник> --vault <vault> --сухой

   Отказ (код 2) — исправить карту и повторить.

П4. **Показ человеку:** список «не знаю, куда» и раскладка из сухого
   прогона. Без «да» дальше не идти.

П5. **Прогон** — та же команда без `--сухой`. Все заготовки —
   `статус: черновик`; повтор ничего не дублирует.

П6. **Сторож** — как шаг 6; папку `модули/перенос/` он пропускает.

## Никогда

- Не догадываться. Нет ответа — «Неизвестное» или «Вопросы», не
  выдуманный факт.
- Не ставить статус выше `черновик` и не ставить ключи «верно» и
  «понятно»: их ставят люди на вычитке.
- Не писать код и не читать код проекта вместо вопросов человеку;
  разработка — круг `/plexus:task` по утверждённой аналитике.
- Не искать аналитику по vault: вход — карточка `capability.md`.
- Не копировать правила, шаблоны и вопросы в этот файл или в чат —
  только ссылаться.
- Не менять тип в плане и не придумывать пятый тип.
- Не коммитить: файлы коммитит человек.
- Не называть файлы идентификаторами: имя по правилу
  `<КОД>-<NN> <что делаем> — <какая проблема>`.
