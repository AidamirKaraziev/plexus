## 2.6.0 — 2026-09-23

Две двери вместо восьми команд: `/начать` и `/закрыть`. Внутри них систему
ведут скиллы и работники — человек не помнит порядок и остаётся в `main`.
Работник круга появился по-настоящему: роль, отчёт из четырёх полей, машинная
проверка отчёта и уборка дорожек.

- `начать` 1.0.0 — вход в сессию: читает только `counters.py`, `streams.py` и
  список открытых кругов, показывает экран «сейчас / дальше / хвосты», задаёт
  один раунд вопросов вариантами и передаёт работу (`/roadmap new`, `/круг`
  или продолжение открытого круга). Своей работы нет
- `закрыть` 1.0.0 — выход: гоняет `проверка:` каждой задачи круга, экран итога
  с расходом из `spend.py`, знание в vault, уборка дорожек, текст коммита.
  Не коммитит и не доделывает за работника
- `круг` 1.3.0 — §7 «Работа по кругу»: очередь задач, запуск работника
  субагентом с `isolation: "worktree"`, приёмка отчёта через `lib/отчёт.py`,
  строка в чат по ходу, экран итога и текст коммита. Размер задачи меряется
  контекстом (200–250k, четверть окна), а не часами; дизайн — отдельная задача
  раньше кода; запись в ledger идёт с «утверждаю», а не с первого коммита
- `lib/отчёт.py` — отчёт работника: четыре поля непустыми, ветка существует,
  команда сверяется с `проверка:` в файле круга; `--роль` проверяет файл роли,
  `--самопроверка` — девять случаев
- `lib/уборка.py` — сносит влитые дорожки работников и их ветки, невлитое и
  грязное оставляет с причиной; `--сухой-прогон` ничего не трогает
- `.claude/agents/программист.md` — роль работника: не написано — не делаю,
  неясно — стоп и вопрос, только выданные файлы, время и токены не пишет
  (их считает скрипт), факт отделён от предположения
- переименованы: `stage-start` → `этап-старт`, `stage-end` → `этап-конец`,
  `stage-merge` → `этап-влить`. Разговорные триггеры сняты со старых имён и
  отданы новым дверям; старый цикл живёт, пока не пройдут три чистых круга

## 2.5.0 — 2026-09-22

Первый кирпич новой системы: скилл `/круг` собирает задание, которое человек
утверждает один раз. Агентов и веток пока нет — только интервью и файл.

- `круг` 1.1.0 — интервью до 100 % (вопросы кнопками, не больше двух раундов,
  догадка запрещена), затем `vault/круги/<имя по смыслу>.md`: цель и «готово,
  когда», задачи с `кому` / `файлы` / критерий / `проверка`, «Решено до
  старта», «Не трогаем». Критерий обязан быть исполняемым; несводимый к
  команде идёт как `проверка: человек`. Решения по критериям (а)(б)(в)
  уходят заметками в vault. Скилл ничего не запускает и не коммитит.
  По итогам первого прогона (задание на E06-S02): вопрос, возвращённый
  человеком «посоветуй», требует рекомендации с «за» и «против» и повтора
  вопроса, а не выбора за человека; проверка задачи не может опираться на
  файл, который делает более поздняя задача — порядок переставить
- Кириллица в именах скиллов проверена: каталог `круг/` подхватывается,
  команда видна как `/круг` — открытый вопрос концепции закрыт
- Дорожки для человека сняты: E06 ведётся в main, дорожки — только для субагентов.
- `aid` 1.6.0 — строка про `/круг`

- `stage-merge` 1.2.0 — вопрос «открыть следующий этап в новой сессии?» снят:
  одна строка `/stage-start E0N`. Остался как «влить прямо сейчас»

## 2.1.0 — 2026-09-13

Дорожки: одна сессия — один эпик — свой worktree. Две сессии по разным эпикам
не мешают друг другу и встречаются только в `main`. Состояние проекта разложено
по эпикам, скиллы коммитить по-прежнему не могут — кроме одного.

- новое: `stage-merge` 1.0.0 — влить ветку этапа в main. Две фазы
  `lib/merge.py prepare|land` с проверками проекта между ними: `prepare`
  коммитит хвост ledger (post-commit хук дописывает хеш уже после коммита,
  файл всегда грязный на одну строку) и вливает main в ветку, конфликт →
  отмена и список файлов; `land` fast-forward'ит чистый main, пересчитывает
  счётчики, отвязывает worktree и удаляет ветку. Любая остановка до `land` —
  main не тронут. Единственный скилл, который коммитит: два `chore`
- новое: `lib/worktree.py` — worktree `.claude/worktrees/E0N` на ветке
  `E0N-S0M` от main; создаёт, переиспользует, перебрасывает на следующий этап,
  отказывает на грязном дереве чужой ветки
- новое: `lib/streams.py` — эпики «Сейчас»/«Дальше» с n/m, следующим этапом,
  наличием worktree, передачи и входящих; `--json` для picker'а
- `stage-start` 1.3.0 — начинает с выбора эпика кнопками, входит в его worktree,
  читает `handoff/E0N.md` и `inbox/E0N.md`; «другая задача» живёт в main без
  дорожки. `counters.py` из старта убран
- `stage-end` 1.4.0 — пишет `handoff/E0N.md` (в main — спрашивает эпик), во
  фронтматтере `ветка:`, в ledger-строке `branch`; в конце спрашивает про
  заметку для другой дорожки и дописывает её в `inbox/E0M.md`; при закрытом
  этапе в worktree предлагает `/stage-merge`
- `aid-project-init` 1.1.0 — создаёт `handoff/` и `inbox/`, `merge=union` для
  ledger, `проект.md` и inbox, игнор `worktrees/`; повторный запуск на старом
  проекте переносит `handoff.md` в `handoff/E0N.md`
- `status` 1.4.0 — передачи читает из `streams.py`, а не из `handoff.md`
- `aid` 1.3.0 — строка `/stage-merge`, ход работы до merge
- `lib/ledger_commit.py` не менялся: лишнее поле `branch` проходит насквозь

## 1.3.0 — 2026-09-09

- новый скилл `aid` 1.1.0 — шпаргалка по своим же командам: что делает
  каждая, когда звать, в каком порядке. Экран лежит в теле скилла готовым и

  команду подробно. Имя не `help`: `/help` занят самим Claude Code
